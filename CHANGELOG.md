# Changelog

All notable changes to AlleleIQ are documented in this file. Format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); from
this point forward, entries are generated by `python-semantic-release`
from [Conventional Commits](https://www.conventionalcommits.org/) on
merge to `main` (see `.github/workflows/release.yml`).

## [0.1.0-alpha] — Initial release

### Added

- **Evidence sources**: async clients for gnomAD v4 (GraphQL,
  per-ancestry allele frequencies and gene constraint), Ensembl VEP
  (REST, consequence/HGVS/REVEL/SpliceAI), and ClinVar (NCBI
  E-utilities, star-rated classifications) — all built on a shared
  retrying, throttled `BaseClient`.
- **VCF parsing**: multi-allelic splitting, parsimonious indel
  normalisation, and GRCh38 build verification (via header or
  contig-length fingerprinting), rejecting GRCh37 input explicitly.
- **Automatable ACMG/AMP criteria** (ACGS 2024-aligned): BA1, BS1, PM2,
  PP3, BP4, PVS1 — each independently testable, never raising, and
  explicitly flagging `requires_clinical_input` when automated
  evaluation is inconclusive.
- **Population coverage gap detection**: every gnomAD v4 ancestry group
  assessed independently against a configurable minimum allele number,
  with WARNING/CRITICAL/NO_DATA severity and specific clinical guidance
  messages — never averaged into a single pooled frequency.
- **Bayesian evidence accumulation** (Tavtigian et al. 2020): point
  totals keyed on applied evidence strength, five-tier preliminary
  classification, conflict detection, and an explicit uncertainty band.
- **Structured JSON and HTML evidence reports**, both rendered from the
  same `EvidenceReport` model so the two formats cannot diverge; the
  clinical disclaimer is enforced at the type level and cannot be
  omitted or altered.
- **CLI** (`alleleiq analyse` / `validate` / `version`) with Rich
  terminal output: progress bars, colour-coded classification summaries,
  and clear error messages with recovery suggestions.
- **FastAPI REST interface** (`/api/v1/variants/analyse[/batch]`,
  `/api/v1/health[/ready]`) with OpenAPI documentation, request-context
  logging, rate limiting, and request size limiting.
- **Known-variant validation** (`scripts/validate_known_variants.py`,
  `alleleiq validate`): runs the full pipeline against 10 real ClinVar
  expert-panel-reviewed variants, reporting a three-way outcome
  (concordant / conservative / dangerous) rather than a flat pass/fail,
  reflecting that AlleleIQ automates 6 of ~28 ACMG/AMP criteria by
  design.
- **Docker**: multi-stage build, non-root runtime user, health check,
  `docker-compose.yml` for local development.
- **Documentation**: full MkDocs site covering architecture, the ACMG/AMP
  and ACGS 2024 implementation mapping, population methodology, clinical
  intended use and safety design, and user guides.

### Known limitations

- Mitochondrial variants are not supported (gnomAD's heteroplasmy-based
  schema differs from the diploid model used elsewhere).
- PVS1's gene-disease validity draws on a small bundled fallback list,
  not a live ClinGen Gene-Disease Validity API integration.
- The in-memory API rate limiter is per-process only; a multi-worker
  deployment needs a shared store.
- No API authentication is implemented; see `SECURITY.md`.
