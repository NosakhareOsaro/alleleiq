# Changelog

All notable changes to AlleleIQ are documented in this file. Format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); from
this point forward, entries are generated by `python-semantic-release`
from [Conventional Commits](https://www.conventionalcommits.org/) on
merge to `main` (see `.github/workflows/release.yml`).

## [0.2.0] — Complete ACMG/AMP automatable criterion coverage

### Added

- **Local REVEL tabix lookup**: population-inclusive PP3/BP4 scoring no
  longer depends on Ensembl VEP reliably returning a REVEL score.
  `scripts/download_revel.sh` builds a bgzipped, tabix-indexed local copy
  of REVEL v1.3 (GRCh38); `REVELClient` queries it directly, handling
  `chr`-prefix and multi-allelic ambiguity, and falls back to VEP REST
  and then "not available" when the local file isn't present. The real
  index is too large for git (REVEL's source data alone exceeds GitHub's
  100MB per-file limit), so it's built locally via the download script
  rather than bundled.
- **ClinGen gene-disease validity and dosage sensitivity**: `ClinGenClient`
  loads bundled ClinGen Gene-Disease Validity and Dosage Sensitivity
  snapshots (`data/clingen/`, refreshed via `scripts/update_clingen.sh`)
  and drives PVS1's strength tiering — DEFINITIVE/STRONG validity with a
  supporting haploinsufficiency score now yields full-strength PVS1,
  MODERATE validity a downgraded strong, and LIMITED/absent curation a
  supporting-only application flagged for clinical review — replacing
  PVS1's previous small bundled-list heuristic as the primary signal.
- **PS1 and PM5** (`scoring/criteria/same_position.py`): same-genomic-position
  ClinVar querying (via NCBI's `chrpos38` positional search) supports PS1
  (same amino acid change as an established ≥2-star Pathogenic/Likely
  Pathogenic variant) and PM5 (a different amino acid change at the same
  position). Both always flag `requires_clinical_input` for manual
  verification; PS1 additionally excludes cases where the variant's own
  splice-impact signal suggests a distinct functional consequence.
- **PP2 and BP1** (`scoring/criteria/gene_level.py`): a curated 50-gene
  missense-mechanism annotation (`data/gene_annotations/missense_constraint.json`)
  supports PP2 for genes where missense variation is an established
  disease mechanism, and BP1 for genes where disease is caused
  specifically by loss-of-function. Genes outside the curated list are
  explicitly marked not-assessed rather than defaulted.
- **PM1 mutational hotspot** (`scoring/criteria/hotspot.py`): combines a
  small curated hotspot list, live UniProt domain/active-site/binding-site
  annotations (`UniProtClient`), and ClinVar variant-density evidence
  (≥3 independent 2+-star Pathogenic records within a positional window),
  withheld when the same region also carries disqualifying benign
  ClinVar variation. Always flagged for clinical review, since domain
  annotation coverage is itself incomplete for many genes.
- **Minimal web interface** (`src/alleleiq/web/`): a server-rendered
  upload → analyse → result flow built on FastAPI, Jinja2, and HTMX
  (vendored, no CDN dependency at runtime), working as a plain HTML form
  with HTMX as progressive enhancement only. Shows live gnomAD/VEP/ClinVar
  connectivity status, streams real per-variant pipeline progress over
  Server-Sent Events during multi-variant analysis, and serves the
  resulting JSON/HTML reports for download. The
  "CLINICAL DECISION SUPPORT ONLY — NOT A CLINICAL CLASSIFICATION TOOL"
  banner is part of the shared base template and cannot be omitted from
  any page.
- **Complete ACMG/AMP automatable criterion coverage**: with PS1, PM5,
  PP2, BP1, and PM1 joining the six criteria already implemented in
  v0.1.0-alpha (PVS1, BA1, BS1, PM2, PP3, BP4), AlleleIQ now automates
  every ACMG/AMP criterion answerable from gnomAD, VEP, ClinVar, ClinGen,
  REVEL, and UniProt data alone.

### Remaining criteria requiring clinical data (by design, not a gap)

After v0.2.0 the only ACMG/AMP criteria AlleleIQ does not automate are
those with no computational proxy: PS2/PM6 (de novo status — requires
parental samples), PS3/BS3 (functional studies — requires wet-lab data),
PS4 (disease prevalence — requires epidemiological data), PP1/BS4
(co-segregation — requires family data), PP4 (phenotype specificity —
requires clinical phenotype), and BP5 (alternate cause found — requires
clinical context). All are correctly flagged `requires_clinical_input`
and remain so — this is the intended boundary between computational
evidence aggregation and clinical judgement, not a limitation to be
engineered away.

## [0.1.0-alpha] — Initial release

### Added

- **Evidence sources**: async clients for gnomAD v4 (GraphQL,
  per-ancestry allele frequencies and gene constraint), Ensembl VEP
  (REST, consequence/HGVS/REVEL/SpliceAI), and ClinVar (NCBI
  E-utilities, star-rated classifications) — all built on a shared
  retrying, throttled `BaseClient`.
- **VCF parsing**: multi-allelic splitting, parsimonious indel
  normalisation, and GRCh38 build verification (via header or
  contig-length fingerprinting), rejecting GRCh37 input explicitly.
- **Automatable ACMG/AMP criteria** (ACGS 2024-aligned): BA1, BS1, PM2,
  PP3, BP4, PVS1 — each independently testable, never raising, and
  explicitly flagging `requires_clinical_input` when automated
  evaluation is inconclusive.
- **Population coverage gap detection**: every gnomAD v4 ancestry group
  assessed independently against a configurable minimum allele number,
  with WARNING/CRITICAL/NO_DATA severity and specific clinical guidance
  messages — never averaged into a single pooled frequency.
- **Bayesian evidence accumulation** (Tavtigian et al. 2020): point
  totals keyed on applied evidence strength, five-tier preliminary
  classification, conflict detection, and an explicit uncertainty band.
- **Structured JSON and HTML evidence reports**, both rendered from the
  same `EvidenceReport` model so the two formats cannot diverge; the
  clinical disclaimer is enforced at the type level and cannot be
  omitted or altered.
- **CLI** (`alleleiq analyse` / `validate` / `version`) with Rich
  terminal output: progress bars, colour-coded classification summaries,
  and clear error messages with recovery suggestions.
- **FastAPI REST interface** (`/api/v1/variants/analyse[/batch]`,
  `/api/v1/health[/ready]`) with OpenAPI documentation, request-context
  logging, rate limiting, and request size limiting.
- **Response caching**: gnomAD population frequency and gene constraint
  lookups are cached process-wide with a configurable TTL
  (`ALLELEIQ_GNOMAD_CACHE_TTL_SECONDS`), avoiding redundant queries
  across the multiple variants in a multi-variant VCF.
- **Known-variant validation** (`scripts/validate_known_variants.py`,
  `alleleiq validate`): runs the full pipeline against 10 real ClinVar
  expert-panel-reviewed variants, reporting a three-way outcome
  (concordant / conservative / dangerous) rather than a flat pass/fail,
  reflecting that AlleleIQ automates 6 of ~28 ACMG/AMP criteria by
  design.
- **Docker**: multi-stage build, non-root runtime user, health check,
  `docker-compose.yml` for local development.
- **Documentation**: full MkDocs site covering architecture, the ACMG/AMP
  and ACGS 2024 implementation mapping, population methodology, clinical
  intended use and safety design, and user guides.

### Known limitations

- Mitochondrial variants are not supported (gnomAD's heteroplasmy-based
  schema differs from the diploid model used elsewhere).
- PVS1's gene-disease validity draws on a small bundled fallback list,
  not a live ClinGen Gene-Disease Validity API integration.
- The in-memory API rate limiter is per-process only; a multi-worker
  deployment needs a shared store.
- No API authentication is implemented; see `SECURITY.md`.
