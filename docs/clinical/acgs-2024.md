# ACGS 2024 Alignment

This page maps AlleleIQ's automated criteria to the specific ACGS
(Association for Clinical Genomic Science) 2024 UK best-practice
guidance points they implement, for reviewers checking alignment against
the current national standard rather than the original 2015 ACMG/AMP
framework alone.

## Points of alignment implemented

| ACGS 2024 guidance point | AlleleIQ implementation |
|---|---|
| BA1/BS1 must be applied with population-specific consideration, not a single pooled frequency. | `population_frequency.py` evaluates every ancestry group independently against `coverage_gaps`; a high frequency observed only in an under-covered population never triggers BA1. |
| PM2 should generally be applied at **Supporting** strength, not Moderate, absent strong gene-disease-specific justification. | `PM2Criterion.default_strength = EvidenceStrength.SUPPORTING`. |
| PP3/BP4 computational evidence should use validated tool-specific thresholds (REVEL, SpliceAI) with tiered strength, not a single pass/fail cutoff. | `computational.py` implements the two-tier REVEL (0.70/0.90) and SpliceAI (0.20/0.50) thresholds for Supporting vs. Moderate strength. |
| PVS1 requires a structured decision tree considering gene mechanism, transcript position (last/penultimate exon), and NMD-escape potential — not a flat "LoF = PVS1" rule. | `lof.py` implements a simplified version of this tree: consequence type → established mechanism (ClinGen Gene-Disease Validity + Dosage Sensitivity, falling back to gnomAD constraint) → exon position. See [ACMG Framework](../architecture/acmg-framework.md) for the explicit simplifications. |
| PS1/PM5 same-position evidence should be corroborated by a properly reviewed ClinVar record (2+ stars), not any submission. | `same_position.py` filters ClinVar positional matches by review-status star rating before applying either criterion, and always flags `requires_clinical_input`. |
| PM1 mutational-hotspot/domain evidence should be withheld where the same region also shows benign variation. | `hotspot.py` checks for disqualifying Benign/Likely Benign ClinVar density in the same region before applying PM1, and always flags `requires_clinical_input` since domain-annotation coverage is itself incomplete for many genes. |
| PP2/BP1 gene-level missense-mechanism evidence should reflect an established, curated gene-disease mechanism, not a blanket assumption. | `gene_level.py` applies either criterion only for genes in a curated, source-cited mechanism list (`data/gene_annotations/missense_constraint.json`); genes outside it are explicitly not assessed rather than defaulted. |
| The evidence-point (Bayesian) framework (Tavtigian et al. 2020) is the recommended quantitative method for combining criteria. | `scoring/bayesian.py` implements this directly, keyed on applied strength. |

## Points of ACGS 2024 guidance not yet automated

As of v0.2.0, ACGS 2024 guidance still extends beyond the eleven
criteria AlleleIQ automates (`PVS1`, `BA1`, `BS1`, `PM2`, `PP3`, `BP4`,
`PS1`, `PM5`, `PP2`, `BP1`, `PM1`) — segregation analysis (PP1/BS4), de
novo confirmation (PS2/PM6), case-control data (PS4), functional-study
evidence (PS3/BS3), reputable-source-without-shared-data handling
(PP5/BP6, now largely deprecated in ACGS 2024 in favour of direct
re-review), alternate-cause findings (BP5), and multifactorial
likelihood-ratio combination for specific gene-disease pairs (e.g.
Bayesian segregation LR in hereditary cancer genes) are all outside
AlleleIQ's current automated scope. These require clinical context,
family data, or functional evidence with no automatable data source, and
are intentionally left for the reviewing Clinical Genetic Scientist
rather than approximated.

## A note on currency

ACGS guidance is revised periodically. AlleleIQ's threshold values
(REVEL/SpliceAI cutoffs, PM2 strength default, coverage thresholds) are
all configuration, not hardcoded constants (see `.env.example` and
`alleleiq.config.Settings`), specifically so they can be updated as
guidance evolves without a code change.
